# Bumping the pin in both consumers

A merge here changes nothing downstream until each consumer moves its pin. Use the same merged full SHA in both, the same day, and paste the suite results in each PR.

1. `fsg-tender-review`: put the SHA in `fsg-common.pin` at the repo root. `ci.yml` installs from it and `scripts/setup_worktree.py` checks the sibling checkout against it. Run `PYTHONPATH=src pytest -q`.
2. `fsg-bluebeam-steel-standards`: put the same SHA in `fsg-common.pin`, run `python scripts/vendor_fsg_common.py` (it refreshes `tools/fsg_common/` byte for byte from this repo's object store, so a `../fsg-common` checkout must hold the commit), then `python tools/tests/test_offline.py`. Do not hand-edit the vendored copy. The share changes only when David runs the copy commands `share-status` prints.

`data/fsg_sections.json` is regenerated by `scripts/refresh_from_workbook.py` from the estimating template. `data/substitutions.json` is the estimator's list, edited by hand with `date`, `decided_by`, `reason` and `source` on every entry. Both consumers read this copy and neither keeps its own.
